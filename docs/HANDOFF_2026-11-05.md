### 2. PP-OCR 교체 (`bb30d84`)
- 새 파일 `lumi/ocr/paddle.py`의 `PaddleReader` (`ports.NicknameReader` 구현). RapidOCR(ONNX)로 인식 모델만 사용 (PaddlePaddle 본체는 Python 3.14 Windows 패키지가 없음).
- 결과를 **점수가 아니라 글자 종류로** 고름: korean 결과에 한글이 있으면 korean, ch 결과에 한자/가나가 있으면 ch, 둘 다 아니면 점수. 점수로 고르면 `ya발견`이 `ya`가 됨. 담당 문자가 아닌 모델 결과는 30점 깎아 API 조회 범위 밖으로 보냄 (오매칭 방지).
- 앞뒤 공백/`.` 제거, 보조 후보(-10점): 넓은 글자 옆 끝의 `1/I/l/|` 제거, 한자 옆 세로선을 `丨`로.
- 빈 칸 생략 기준 0.02 (Tesseract는 0.05). 실게임 2880×1800에서 두 글자 닉네임 `르채`가 0.046이라 빈 칸으로 생략됐었음. 빈 칸은 최대 0.036이고 읽어도 점수 35 미만.
- 모델은 시작할 때 미리 로드 (RapidOCR는 첫 호출 때 로드해서 첫 매칭이 1.5초 느렸음).
- 설정 `LUMI_OCR_ENGINE` (기본 `paddle`, `tesseract` 가능). rapidocr가 없으면 자동으로 Tesseract. 선택은 `lumi/ocr/__init__.py`의 `make_reader`.
- `requirements.txt`에 `rapidocr`, `onnxruntime` 추가. 첫 실행 때 ModelScope에서 모델 약 30MB 다운로드 (venv의 `site-packages/rapidocr/models/`).
- `lumi/ocr/chars.py`의 `LINE_LIKE_CHARS`에 `−`(U+2212) 추가 (PP-OCR이 UI 선을 `———−`로 읽음).
- 테스트: `tests/test_paddle_reader.py`, 픽스처 `tests/fixtures/crop_2880x1800_short_hangul.png` (`르채`).
- 결과: 1순위 정답 24/25, API 조회 후보 포함 25/25, 칸당 약 200 ms.
